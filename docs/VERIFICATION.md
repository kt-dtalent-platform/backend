- 보완 항목 반복 조회의 일괄 조회 전환.

- 조회 열 정보·검증 목록 재사용.
- JSON 변환 중복 및 임시 객체 축소.
- Java·설정 주석의 짧은 명사형 통일.
- 실행 JAR 80.8MB에서 52.1MB로 축소.
- 기존 마이그레이션 원본 유지.

## 확인한 동작

- 실제 HTTP 서버·DB 상태 API UP, 내부 상세 미노출.
- 로그인, refresh 일회 회전, 로그아웃·비밀번호 변경 시 토큰 폐기, 5회 실패 잠금.
- 장학생 본인 자료 접근, 다른 장학생 및 담당 범위 밖 관리자 접근 차단, 기수별 범위 통제.
- 프로그램·기수 생성과 권한 부여, 공개 시 대상 명단 고정, 커서 페이지네이션.
- 작성·제출·항목별 보완·재제출·확인 완료, 이전 자료와 변경 이력 보존.
- 동시 수정은 한 요청만 성공하고 다른 요청은 version 충돌로 거절.
- 마감 이후 일반 신규 제출 거절, 담당자가 요청한 보완 건만 예외적으로 재제출 허용.
- 파일 바이트 시그니처·확장자·소유권·누적 저장 한도·제출 파일 보존.
- XLSX 출력과 감사 기록. 미작성·작성 중 대상이 필터에 포함되고 제출 완료 후 제외되며, 미제출 조회 결과와 XLSX의 이메일이 일치하는지 확인.
- OCR 미설정 실패, 모의 추출 결과에 대한 서버 비교, 입력 변경 시 결과 무효화, 파일당 5회 제한.
- F 감지·F 여부 불명·필드 누락은 자동 MATCH 불가. 학교·학기·성적 불일치 판별.
- UTC 시간 왕복 보존, 잘못된 FK·ENUM·중복 이메일 거절.

이전 V3 기준 측정값은 테이블 18개, 컬럼 154개, FK 27개다(Flyway 이력 테이블 제외). 이번 검증에는 V4 마이그레이션도 적용했다.

## 재현 시 주의

MySQL에서 테스트하려면 별도의 빈 검증 전용 DB를 만들고 TEST_DB_URL, TEST_DB_USERNAME, TEST_DB_PASSWORD를 설정한다.
그 상태에서 `gradlew.bat test --rerun-tasks`를 실행한다. **테스트는 매 케이스마다 해당 DB의 업무·사용자 데이터를 삭제하므로 개발·운영 DB를 지정하면 안 된다.**
환경변수가 없으면 기본 H2 임시 DB를 사용한다.

## 검증 범위 밖

실제 OCR 공급자·학교별 실물 인식률, 실제 개인정보 운영, 1년 자동 파기, 백업 복구, 배포 서버의 TLS·디스크 암호화·악성 파일 검사는 검증하지 않았다.
API 동작 검증을 운영 보안 인증이나 재단 실사용 승인으로 해석하면 안 된다.
