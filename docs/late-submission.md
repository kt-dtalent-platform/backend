# 마감 후 제출

## 적용 범위
공개된 IN_PROGRESS 요청은 유효 기한이 지나도 임시저장·파일 발급/완료/삭제·최종 제출·재제출을 받는다. 기존 대상자·본인 권한·버전·필수 입력·파일 완료·보완 항목 제한은 유지한다. CLOSED 요청은 기존처럼 막는다.

가장 최근 최종 제출 또는 재제출 시점이 학생의 유효 마감 이상이면 기존 submissions.is_late에 true를 저장한다. 유효 마감은 extended_due_at이 있으면 그 값, 없으면 requests.closes_at이다. 처음 제출한 submitted_at은 재제출로 덮어쓰지 않는다. 기한만 바꾸어 이미 저장된 지연 판정이 바뀌지는 않으며, 다음 재제출 시에는 그때의 유효 마감으로 다시 판정한다.

새 마이그레이션은 없다. 과거 제출의 기본값 false를 일괄 추정·보정하지 않는다.

## 프론트 연결
- 기존 담당자 제출 현황·상세 API의 late(boolean)가 저장된 is_late를 그대로 반환한다. true면 ‘마감 후 제출’ 태그를 표시한다.
- GET /v1/dashboard/manager: review.late(전체 건수), requests[].late(요청별 건수)를 추가한다. 기존과 같은 공개 IN_PROGRESS 요청·프로그램/기수 필터 범위이며 DRAFT는 세지 않는다. 보완 필요·확인 완료라도 저장된 late가 true이면 센다.
- late만 따로 조회하는 서버 필터는 추가하지 않았다. 서버 페이지 필터가 필요하면 승완의 제출 현황 API와 계약을 맞춰야 한다.

## 별도 합의·승완 연결
- 1분마다 공통 기한이 지났고 미래의 개별 연장·보완 기한도 없는 공개 IN_PROGRESS 요청을 CLOSED로 바꾼다. 보완 기한은 기존 extended_due_at 저장값을 함께 확인한다. 대상자가 없는 요청도 공통 기한 이후 종료한다. 최종 기한 경과 후 다음 실행까지 최대 약 1분 동안 접수될 수 있다. 담당자 마감 API·마감 확인창은 추가하지 않는다.
- CLOSED 뒤 보완 대상만 재제출할 수 있게 할지도 별도 합의 대상이다. 이번 변경은 열린 요청의 지연 제출에 한정한다.
- ReviewDecisionService는 ‘지난 기한 뒤 dueAt 없는 보완 요청’을 거절한다. 지연 제출 허용과 별도로 보완 기한을 계속 필수로 둘지 승완이 확인해야 한다. 해당 코드는 수정하지 않았다.
- 프론트·승완 인증/요청/검토 소스는 수정하지 않았다.
