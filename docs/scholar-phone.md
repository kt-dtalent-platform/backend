# 장학생 연락처 저장

등록·수정·JSON 일괄 등록에서 연락처의 숫자 이외 문자를 제거한 뒤, 0으로 시작하는 9~11자리인지 검증한다. 예: `(010) 1234-5678` → `01012345678`. 형식이 맞지 않으면 400이며, 일괄 등록은 행 번호·phone 오류를 반환하고 전체 저장을 취소한다.

연락처는 기존처럼 선택 입력이다. 등록에서 null·생략을 허용하며, 수정에서 생략하면 기존 값을 유지한다. 문자열을 보냈는데 숫자가 없거나 길이·첫 자리가 맞지 않으면 400이다. 프론트의 표시 형식은 별도로 적용한다.

V12는 기존 scholar_profiles.phone에서 숫자 이외 문자를 제거한다. null은 유지하며 숫자를 임의로 채우거나 바꾸지 않는다. 기존에 번호 자체가 잘못 저장된 데이터는 자동 복구할 수 없으므로 배포 전 아래 조회 결과를 확인하고 실제 번호를 확인해 정정해야 한다.

```sql
SELECT user_id
FROM scholar_profiles
WHERE phone IS NOT NULL
  AND REGEXP_REPLACE(phone, '[^0-9]', '') NOT REGEXP '^0[0-9]{8,10}$';
```

프론트에서 추가로 요청 형식을 변경할 필요는 없다. JSON 일괄 등록 `/v1/scholars/bulk`에도 동일한 규칙을 적용한다.
