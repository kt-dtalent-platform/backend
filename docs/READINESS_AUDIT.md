# 상용 운영 준비도 점검

점검일: 2026-10-31

## 판정

**실제 개인정보를 사용하는 상용 운영 보류.**

현재 수준은 기본 흐름을 구현하고 테스트한 MVP 백엔드다. 기존 21개 테스트 통과는 정상 흐름과 일부 방어 조건의 근거이며, 장애 복구·개인정보 수명주기·실제 배포 안전성의 보장은 아니다.

| 사용 단계 | 판정 |
|---|---|
| 합성 데이터 개발·시연 | 가능 |
| 실제 서류를 받는 폐쇄형 파일럿 | 우선 항목 수정 및 운영 검증 전 보류 |
| 상용 고객 운영 | 보류 |

## 범위

- 인증·권한·업무·제출·파일·분석 코드와 설정 검토.
- 별도 H2 DB, 합성 계정, 검증 전용 파일을 통한 재현 검사 5건.
- 로컬 HTTP 서버를 통한 JDK 응답 스트림 시간 제한 검사.
- 실제 런타임 Maven 패키지 86개의 OSV 조회.
- 애플리케이션 코드·기존 데이터·GitHub 변경 없음.

실제 운영 서버, 프론트 토큰 보관, OCR 공급자, 백업 저장소, TLS 설정, 부하·침투 테스트는 점검 범위 밖이다. OWASP ASVS 일부 관점을 참고한 자체 점검이며 전체 ASVS 인증 결과가 아니다.

## 재현 결과

아래 5건은 문제가 발생하는 현재 동작을 확인한 재현 결과다. 수정 완료 결과가 아니다.

### R1. 파일 삭제와 DB 롤백 불일치

- 우선순위: P1.
- 근거: `FileService.java:183` 원본 삭제 후 DB 상태 변경.
- 재현: 업로드 완료 파일의 삭제 과정에서 DB 갱신 예외 주입.
- 결과: DB 롤백으로 `upload_status=UPLOADED` 유지, 실제 파일 소실.
- 범위: 삭제가 허용되는 작성 중 첨부 파일. 이미 제출한 원본은 삭제 차단으로 이 재현 대상에서 제외.
- 영향: 오류 응답 이후 DB·저장소 불일치, 다운로드 실패, 물리 삭제 이력 누락 가능성.
- 조치: 영속 삭제 작업 및 재시도·보상 처리, 장애 후 DB·저장소 정합성 검사.

### R2. OCR 전체 처리 시간 제한 미보장

- 우선순위: P1.
- 근거: `OcrClient.java:53`의 `ofInputStream`과 `:56`의 본문 읽기. `AnalysisService.java:13` 트랜잭션과 `:35` 제출 행 잠금.
- 재현: 로컬 HTTP 서버에서 헤더와 본문 첫 부분을 전송한 뒤 본문 완료 지연.
- 결과: JDK 요청 제한 500ms 설정에서도 본문 읽기 1,543ms 지속.
- 범위: 실제 OCR 공급자의 장애 재현이 아닌, 동일 JDK 스트림 수신 방식의 동작 검증. 운영 코드의 25초 설정만으로 전체 처리를 25초로 보장할 수 없는 근거.
- 영향: 공급자 본문 지연 중 DB 트랜잭션·행 잠금·연결 유지. 동시 요청 누적 시 전체 서비스 가용성 저하 가능성.
- 조치: 본문 완료까지 포함한 전체 기한, 동시 실행 상한, 외부 호출과 DB 트랜잭션 분리, 결과 반영 시 파일·입력 버전 재검사.

### R3. 파일 내용 검증 부족

- 우선순위: P1.
- 근거: `FileService.java:161`의 앞부분 바이트 검사.
- 재현: `%PDF-1.7` 뒤에 PDF 구조가 아닌 일반 문자열을 붙여 업로드.
- 결과: `UPLOADED` 등록 및 담당자 다운로드 성공.
- 영향: 실제 PDF 구조·이미지 디코딩 검증과 악성 파일 검역 부재. 이 검사는 서버 코드 실행이나 실제 악성 PDF 실행을 입증한 결과는 아님.
- 조치: 허용 형식의 구조 검증, 격리 상태, 악성 파일 검사 및 검사 완료 전 열람 차단. 처리 도구 자체의 자원 제한·패치 관리 포함.

### R4. 기본 프록시 환경의 로그인 한도 충돌

- 우선순위: P1, 배포 구성 의존.
- 근거: `SecurityConfig.java:98`의 `getRemoteAddr()` 기반 프로세스 메모리 제한.
- 재현: 같은 연결 주소에서 서로 다른 `X-Forwarded-For`를 보낸 20건의 로그인 실패 후 다른 정상 계정 로그인.
- 결과: 정상 비밀번호를 보낸 별도 계정에도 HTTP 429.
- 범위: 신뢰 프록시의 원본 주소 처리가 없는 기본 구성. 실제 운영 프록시 설정은 미확인.
- 영향: 프록시 주소 공유 시 사용자 전체가 하나의 분당 20회 예산 공유. 다중 인스턴스에서는 인스턴스별 한도 분산.
- 조치: 신뢰 프록시 경계 설정, 계정·클라이언트 기준 제한 설계, 공유 게이트웨이 또는 저장소 적용. 임의 전달 헤더의 무조건 신뢰 금지.

### R5. 저장 파일 무결성 미검증

- 우선순위: P2.
- 근거: `FileService.java:64`의 원본 읽기. 업로드 시 저장한 SHA-256과 재대조 없음.
- 재현: 검증 전용 저장 파일을 업로드 이후 변경한 뒤 다운로드.
- 결과: DB의 기존 체크섬 유지 상태에서 변경된 바이트 반환.
- 범위: 테스트가 저장소에 직접 변경을 가한 경우. 원격 사용자의 저장소 쓰기 권한 획득을 입증한 결과는 아님.
- 영향: 원본 손상 또는 저장소 한쪽 변경의 미탐지.
- 조치: 파일 크기·체크섬 검증, 불일치 격리·알림, 복구 절차.

## 의존성 점검

- 방식: Gradle 런타임 해석 결과의 패키지·버전을 OSV `/v1/querybatch`에 조회.
- 패키지: 86개.
- 응답: 86개.
- 등록 취약점 매칭: 0건.
- 한계: 미등록 취약점, 데이터베이스 수집 지연, OS·JDK·컨테이너·프론트 의존성, 설정·업무 로직 취약점 제외. 악용 가능성 분석 및 전체 보안 검증의 대체 근거로 사용 불가.

## 우선순위

1. R1·R2 장애 경로와 R3 파일 검증 보완.
2. 개인정보 저장·파기·백업·복구 기준 확정 및 구현.
3. 실제 프록시 환경의 인증·제한·계정 운영 검증.
4. 프론트·OCR 연결 후 실제 업무 경로와 예외 검증.
5. 부하·장애·보안 검사와 운영 승인.
